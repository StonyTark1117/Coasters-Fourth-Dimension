# FD401C selected-JAR Legacy normal boarding and unload

On 2026-11-05, the exact selected clean `ec2fcda` JAR (`656725bcbacc8f491de274c6c058027d0aaa67cfc6f893ba6d7e4a9eb24abbc7`) loaded a copy of the stopped, normally built Legacy world in the combined Styles 1.2.0 + Engineered 1.1.1 profile. Java 21 ran the client in private Xvfb `:257` with a 1 GiB game heap inside an active 3 GiB systemd scope. The scope exited with `Result=success`; the client and owned display stopped after a normal world save and exit.

Dev started unassigned. With the normal right-mouse Use binding and an empty hand, the player moved to `(197.5,145,31.5)` facing north at pitch 40. [F3 targeted](target.png) the unrestrained physical `fourthdimension:legacy_seat` at native `(20481032,127,20491273)`. One default right click produced a server `FD_BOARDING_EVENT action=mount` and `FD_BOARDING_ASSIGN accepted=true` for that exact seat. The [mounted view](boarded.png) showed the dismount prompt; `/data get entity Dev RootVehicle` showed a [Create seat entity](mounted-rootvehicle.png). Holding Shift then logged `action=dismount`; the next RootVehicle query returned [no elements](unloaded-rootvehicle.png). The client reached the [title screen](title.png) and the log ended with normal server and client shutdown.

The earlier failed clicks were at `(197.5,145,32.5)` or farther, at pitch 25. A **separate diagnostic JAR** (`b9a7a888…`) changed only `FourthDimension.class` and `CarrierSeatBlock.class`, as listed in [the comparison](diagnostic-jar-compare.txt) and [source patch](diagnostic-source.patch). Its [log](diagnostic-client.log.gz) found the target seat bound, ready, unrestrained, unoccupied, and within client/server interaction distance, but the client's actual Use hit result at the old pose was `MISS`. Moving closer and aiming down made the diagnostic input reach the block and mount. The clean-JAR run above independently confirms normal boarding and unload; the diagnostic run is **not** acceptance evidence for that claim.
