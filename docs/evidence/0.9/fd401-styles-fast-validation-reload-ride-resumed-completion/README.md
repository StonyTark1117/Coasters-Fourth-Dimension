# FD401B FAST validation reload and resumed ride completion

This directory combines the initial partial FAST attempt with its saved-world continuation. It records one continuous ride scenario across separate client launches; it is not an independent fresh reload-and-ride repetition. The initial run performed the reload and dispatched the selected Arrow train. Its first normal UI Dispatch immediately returned the Rotation Tool status to Ready while the saved station signal remained high. The scratch-world redstone block at `-356 210 -179` was cleared to allow motion. The client was saved and quit while Dev remained mounted. On continuation, the copied intermediate world restored Dev riding; the redstone block was restored once, the car returned and reported `capture=true`, the Rotation Tool showed Ready with restraints closed, restraints were opened, and Shift dismount completed. `/data get entity @s RootVehicle` then returned `Found no elements matching RootVehicle`.

The run used the selected packaged JAR with SHA-256 `656725bcbacc8f491de274c6c058027d0aaa67cfc6f893ba6d7e4a9eb24abbc7` (source commit `ec2fcda`). The first launch used Java 21.0.13, a 768 MiB heap, display `:252`, and a task-owned systemd scope capped at 3 GiB; it had validation disabled and performed F3+T. The later helper launch and continuation used the same selected JAR and copied VM arguments enabling `-Dfourthdimension.validation=true` for the owner-authorized `/fd validation board_locked Dev` helper. The continuation used Java 21.0.13, a 768 MiB heap, display `:252`, and its own 3 GiB scope. The scratch game directory was `/tmp/fd401b-fast-20261105/game` for the partial attempt and `/tmp/fd401b-fast-resume-20261105/game` for the continuation. Graphics mode was FAST (`graphicsMode:0`); render and simulation distance were 4 in these resumed-run copies. Minecraft logged that simulation distance 4 was below the valid 5–17 range and normalized it on load.

The selected JAR hash is also recorded in `partial-attempt/mod-jar.sha256`. Launch inputs and dependency hashes are in `launch-args/`. `worlds/input-world.tar.gz` is the original selected Arrow fixture. `partial-attempt/final-world.tar.gz` preserves the intermediate save with Dev mounted and the station signal cleared. `worlds/resumed-final-world.tar.gz` is the completed save after capture, normal dismount, and save/quit. Screenshots and full client logs from both phases are in `partial-attempt/` and `resume-continuation/`.

This evidence proves occupied movement, capture after the disclosed signal restoration, UI restraint opening, and normal Shift dismount. It does not prove a sustained normal UI dispatch: with the station signal high, the UI Dispatch immediately showed Ready again. Boarding used the authorized validation helper after normal targeting missed the Arrow seat; normal boarding is left to the separate FD401C slice.
