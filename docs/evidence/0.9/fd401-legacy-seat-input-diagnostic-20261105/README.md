# FD401C Legacy seat input diagnostic (no operator pass)

This is a targeted follow-up to the [clean-JAR Legacy mount miss](../fd401-engineered-clean-combined-legacy-seat-blocker/README.md), not a repeat acceptance cycle. On 2026-11-05, a Java 21 client loaded an **instrumented diagnostic JAR** from an isolated export of committed source `ec2fcda` with Styles 1.2.0 and Engineered 1.1.1. The only changed JAR entry relative to selected clean JAR `656725bc…` is `CarrierSeatBlock.class`, as verified in [artifact-comparison.json](artifact-comparison.json). Its [instrumentation patch](instrumentation.patch) prints `FD_SEAT_CLICK` from `CarrierSeatBlock.board()` whenever `fourthdimension.validation=true`; the launch VM arguments set that property. The diagnostic JAR SHA-256 is `4b4eeb947829b3dc36eded6bd53c081970c7756493e933cb913c0016db1b7368`, retained as [instrumented.jar](instrumented.jar). This is not the qualification artifact.

The client loaded a copy of the retained stopped Legacy world from the first attempt. At `(300.5,185.3,126.5)` and then the closer `(301.5,185.3,128.5)`, F3 targeted `fourthdimension:legacy_seat` in the native carrier ([first target](f3-target.png), [closer target](closer-f3.png)). One empty-hand right click at each position did not board. Neither the [console](console.log.gz) nor [game log](game.log.gz) contains `FD_SEAT_CLICK` or a boarding event. Thus the attempted input did **not reach the instrumented seat method**, as far as this runtime log can observe. This does not test `Boarding.canBoard/ready` and does not establish a gameplay defect: the remaining possibilities include client input routing, reach, native sublevel interaction forwarding, or the Xvfb automation path. No dispatch/STOP/capture/unload was attempted.

The private task-owned Xvfb display was `:241`; the direct [launch script](run-client.sh) set `-Xmx1024M` and ran in active `run-p320257-i333609.scope` with `MemoryMax=3221225472`. `MemoryCurrent=2432552960` was observed while active. The client saved through the normal menu, exited with `Result=success`, and then the owned display was stopped. The [build log](build.log.gz), [dependency hashes](dependencies.sha256), [final copied world](final-world.tar.gz), and [title image](title.png) retain the environment and exit. Further Legacy client repetition should wait for a concrete interaction-route change or a different input method that can be shown to deliver block use events.
