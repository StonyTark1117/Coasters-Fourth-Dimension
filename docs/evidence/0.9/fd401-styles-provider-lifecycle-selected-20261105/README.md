# FD401B selected-JAR Track Styles provider absence and return

The input was the saved Styles-only Arrow world from [the selected-JAR tracing-disabled ride](../fd401-styles-tracing-disabled-reload-ride-ec2fcda-20261105/README.md). Its `final-world.tar.gz` is the reproducible world input. This run copied it into an isolated game directory, launched the **base** profile without Track Styles, saved and exited, then copied that saved world into a second isolated game directory and launched the **Styles-only** profile. Both classpaths use the exact selected `ec2fcda` mod JAR, SHA-256 `656725bcbacc8f491de274c6c058027d0aaa67cfc6f893ba6d7e4a9eb24abbc7`. The base classpath has ten loaded mods; the Styles classpath adds Track Styles 1.2.0. Both runs used Java 21 and separate direct-Java launch scripts derived from the retained client argument files.

The base client loaded and rendered the world without Track Styles, then saved and exited successfully. The Styles client loaded the **base-saved** world, logged `FD_OPTIONAL Track Styles 1.2.0: inspected 55 decorative model entries`, and visibly rendered a blue double-spine styled Arrow section near `(-342,210,-148)` in `styles-styled-rail.png`. It also saved and exited successfully. Both used task-owned Xvfb `:274`, restarted between runs. The base run used a 1 GiB heap in a verified 3 GiB scope; the Styles run used a 1 GiB heap in a verified 6 GiB scope, matching the revised AGENTS.md limit that arrived between runs. The `:274` display and both client scopes are stopped.

The retained `fourthdimension_foundation.dat` files and `read-foundation.py` decode to the JSON reports here. Comparing **all 24 rail records**—endpoints, family, variant, identity, revision, geometry hash, rotation profile and appearance—gives exact equality from input to base save to Styles save. Three rails retain Track Styles appearance IDs: two `arrow_4d_dbl_spine`, one `arrow_4d`. Thus missing provider load/save did not discard those cosmetic choices or change their recorded mechanical rail state, and the provider could be reinstalled on the same world.

This is a bounded persistence and static rendering result. The base screenshot is not aimed at one of the three styled sections, so it does not directly prove the **visual** Original fallback at a styled section while the provider is absent. It does not include an occupied ride, UI style edit, or dynamic geometry comparison. Those FD401B acceptance rows remain open. The complete copied worlds and uncropped logs remain under `/tmp/fd401b-provider-lifecycle-20261105` on this host; the input world is also retained in the linked earlier bundle.
