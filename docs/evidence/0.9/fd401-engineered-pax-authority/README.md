# FD401 Engineered motor against an occupied PAX winch cycle

The packaged NeoForge client ran with `-PfdPackaged -PfdValidation -PfdIntegrations=engineered -PfdFeNetwork` and `requireEnergy=true` on the continued `FD401FamilyBare` world. The shipped `/fd demo pax` fixture built the PAX route and four-car shuttle at origin `(650,144,65)`. The fixture's Create creative motor drove the winch at `(644,144,73)` at 128 RPM; this is an authority test, not physical FE-generation evidence. The player fitted an Engineered linear motor by its normal item to the low track anchor `(650,144,65)`, spanning the first 10 blocks toward positive Z (`T0=0`, `T1=0.3125`), then placed and linked a normal controller at `(644,144,67)`. The controller retained its default `Launch 20 → End` program. A command supplied 100,000 FE directly to the motor as a disclosed fixture input.

The player boarded an actual PAX seat, closed the four-car train's restraints in the in-ride editor, and pressed **Dispatch**. The winch entered `LIFTING` with the player on the lead car. A redstone block at `(644,144,68)` powered the Engineered controller during the lift and remained in place throughout outbound, return and capture. The [challenge screenshot](lift-challenge.png) shows `LIFTING`, `CoastersEngineeredPass=0`, `CoastersEngineeredDriving=0`, and the motor still at 100,000 FE. The [completed cycle](captured.png) shows `shuttle_phase=BOARDING`, `shuttle_cycles=1`, and the rider back near `z=73.5`; the later [controller/energy query](complete.png) still shows pass zero and 100,000 FE. The [in-ride editor](return-editor.png) reported Ready with restraints closed. The player removed the redstone block, opened restraints normally, Shift-dismounted, and [availability](availability.png) returned `assignments=0`.

This establishes one occupied winch cycle with an opposing powered Engineered controller and normal capture/unload. It does not expose a per-car rejected motor callback during every traversal of the fitted span; pass and FE remaining zero are externally observed outcomes. Source `EngineeredInterlock.holds` explicitly holds every `Family.PAX` car, and the optional motor mixin cancels its apply callback. Existing native interlock assertions remain the direct callback-level reference.

The [raw client log](client.log) names the loaded packaged JAR path and ends with `All dimensions are saved` and Gradle `BUILD SUCCESSFUL`; the [stopped world archive](world.tar.gz) preserves the result. [SHA-256 inventory](evidence.sha256) covers all retained payloads. Another actor built in the shared output directory during this session, so the post-run file hash does not establish the exact in-use runtime JAR identity. No release freeze or artifact-equivalence claim is made here.
