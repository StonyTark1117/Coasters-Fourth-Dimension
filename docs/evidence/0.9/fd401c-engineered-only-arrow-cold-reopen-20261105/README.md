# FD401C Engineered-only Arrow cold-reopen evidence

This bundle verifies the cold-reopen slice on an inherited selected-JAR Engineered-only Arrow route. It does not prove a fresh route, a new pass, FE interruption, Launch 20 acceptance, or a full circuit. Both clients used the retired 3 GiB process scope because I failed to read the current `AGENTS.md` before launching. The observed behavior remains a bounded functional result; future launches use the current 6 GiB default, and this fixture should not be repeated solely to relabel the scope.

`run-manifest.json` gives the exact JAR/archive hashes, Java/profile/scope details, outcomes, and evidence map. `world-before.sha256` hashes the extracted archived world. `world-after-open1.sha256` hashes the first normally saved world containing the assigned, restraints-closed rider; `checkpoint-assigned-restraints-closed.tar.gz` is that stopped checkpoint. After cold reopen the rider automatically restored with closed restraints at the captured station and remained at the same motion position across an idle interval. The operator then opened restraints, dismounted, and saved. `world-after-reopen.sha256` and `world-after-reopen-and-dismount.tar.gz` contain that final world. `playerdata-after.json` confirms RootVehicle was cleared by the normal dismount.

Both process logs and debug logs are retained as `open-1-*` and `open-2-*`. The screenshots document the Arrow seat target, initial normal boarding and restraints closure, saved/reopened UI state, stable motion samples, normal dismount, and both save/exit screens. `selected.jar`, classpaths, launch args, and the 1536M wrapper preserve run identity. All files are covered by `SHA256SUMS`.
