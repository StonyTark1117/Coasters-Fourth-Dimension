# Fresh PAX normal-construction and occupied-cycle observation

This run used the selected packaged candidate `coasters-fourth-dimension-0.9.0-dev.27.jar` (SHA-256 `656725bcbacc8f491de274c6c058027d0aaa67cfc6f893ba6d7e4a9eb24abbc7`) in an isolated fresh client/world. It closes the fresh PAX construction and one occupied cycle slice; it is not a declaration that all FD401C requirements are complete.

The PAX track spans, four PAX cars, three chain links, and winch were placed or configured through normal held items and UI controls. Their inventory was supplied with `/give`. Upstream coaster anchor/support blocks were placed by `/setblock` to provide clear endpoints, and the Create creative motor underneath the winch was also command-placed to provide the disclosed 16 RPM source. Therefore this demonstrates normal PAX construction and operation against command-fixtured route supports and power; it does not demonstrate a fully normal electrical/mechanical source build.

The four-car winch reached `BOARDING`, bound four cars, and had a clear fault field. Dev boarded a native PAX seat, closed restraints, dispatched, and completed one cycle: the winch passed `LIFTING` and `OUTBOUND`, returned to `BOARDING`, and retained `shuttle_cycles: 1`. `FD_BOARDING_EVENT` records the normal mount and dismount. `FD_BOARDING_DISMOUNT_CLEAR` records the post-run restraint-open dismount. The final console NBT probe records phase, distance, fault, cycle count, and car UUIDs. The client saved all dimensions, exited with systemd result `success`, and its private display was stopped.

The only `FD_CLIENT_TELEMETRY` snapshots emitted in this run are initial availability and the valid `BOARDING` state; the available log does not show sampled LIFTING/OUTBOUND/CAPTURING telemetry snapshots. Those richer phase telemetry rows remain open under FD401D.
