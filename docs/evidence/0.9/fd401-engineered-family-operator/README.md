# FD401 Engineered family operator loops: Legacy, Free Spin, Revised

Three packaged NeoForge client sessions used `-PfdPackaged -PfdValidation -PfdIntegrations=engineered -PfdFeNetwork` with `requireEnergy = true`. They ran successively on the saved [normally item-placed Arrow world](../fd401-engineered-wired-waterwheel/README.md), with one separate bare circuit per family. Each session saved all dimensions and exited with Gradle `BUILD SUCCESSFUL`. [SHA-256 inventory](evidence.sha256) covers the complete raw logs, screenshots and successive world archives. The shared build output was used during a concurrent `main` commit, so exact runtime-JAR hashing needs a controlled freeze; the logs name the loaded packaged JAR path.

The validation-only `engineered_loop legacy|free_spin|revised` commands create the original eight-edge track and an empty station, without a native chain drive or car. This is needed because the shipped `/fd demo` circuits preinstall chain-lift shafts on every anchor, which Engineered's motor item rejects as a start anchor. On each bare route the player used the actual motor item to fit the first 10 blocks of the straight (`T0=0`, `T1=0.27777780568955546`), placed the matching car by ordinary item right click, bound the station by empty-hand click, placed and linked a controller through its item UI, and programmed [`Launch 8 → Stop at 8 → End`](legacy-program.png) through its GUI. The controller program screenshots for [Free Spin](free-spin-program.png) and [Revised](revised-program.png) show the same sequence.

For each family, a fixture command supplied 100,000 FE to the motor anchor. This is a disclosed input for family behavior, not evidence of FE generation or wiring; the separate [wired water-wheel run](../fd401-engineered-wired-waterwheel/README.md) covers that path. The player boarded a real seat by empty-hand click, closed restraints in the in-ride editor, raised and released the station rear redstone input, then pulsed the linked controller. The rider completed an occupied circuit, the controller entered the programmed STOP, station rear redstone captured the car, and the player opened restraints and Shift-dismounted. FE fell during each ride.

The Legacy car was first placed outside the original station's eight-block range. The first station release therefore did not dispatch; received telemetry reported `Vehicle is outside station range`, and the controller pass remained zero. The fixture moved only the station closer to the same car and track. The player rebound it normally, boarded again, and completed the recorded pass. This failed first attempt is retained in `legacy-client.log`.

Availability returned to `assignments=0` after each unload. The denominator grows across the successive worlds; unloaded distant cars are therefore absent from the numerator when the player teleports to the next circuit. These results cover the three previously missing non-PAX families with real car placement, controller and rider controls. The coupled Arrow train and PAX winch-versus-motor authority remain separate parts of the same FD401 family gate.
