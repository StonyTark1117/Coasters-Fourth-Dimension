`MovingProgramSpec` restricts serialized configuration to finite mechanism presets. `MovingProgram` produces rigid physical pose targets (yaw then local pitch) for transfer, turntable, drop, tilt, elevator, teeter, side-drop and compound motion. Continuous swept volumes include the rotated full envelope between samples, using conservative angular padding rather than only endpoint hulls. Runtime admission includes bed geometry, every chassis and child body, NG Flying's intermediate deck, declared original vehicle envelopes, mounted entity bounds and the convex between-car coupler reservation. Train-only bounds are separately supplied for receiving-span length.

Recovery replans from rest on the original prescribed path. The recovery cursor maps fragment progress back to original program time, allowing repeated interruptions without serializing arbitrary path fragments. Measured stopped native pose is projected only onto the saved original leg and a bounded neighborhood; off-path error and alternative full-revolution branches are rejected. Projection is not a teleport and does not establish a native physical tolerance by itself.

## Route and released-service handling

The actual moving bridge has a scoped read-only route view. Candidate validation never writes synthetic rails into `FoundationData` and never publishes native traversal. Live bridge lookup requires the native adapter's registered, physically locked, aligned and stopped bridge. Wing and the empty ordinary cart retain ordinary unmarked native track; other configurations receive their exact authenticated neutral service descriptor.

Complex family adapters reuse their existing fixed-route validators and actual controller ownership. NG Flying fixed sections still require real authored yaw/posture intervals and owned targets. Powered Yaw retains real speed/yaw programs and governor route ownership. Flying Bike retains its original two launch bindings. Roller Ball retains its ordered route. PAX uses its unchanged original fixed station and bounded native carriage approach/catch recovery; its dedicated physical recovery acceptance remains separate. Original station coordinates are never relabeled to a new gap.

Released FD cars preserve the measured local parent/child posture with temporary native joints. The saved state contains exact measured joint frames and body IDs; it does not reconstruct posture from a preset. Normal dispatch remains explicit. Service posture is released only after the complete car envelope clears the bridge and the actual fixed exit passes its family checks. Cold reload and bridge loss retain the recorded service membership and require explicit recovery. Stopped chassis use a measured native world hold; missing bodies remain faults, not successful cleanup or evacuation.

Empty ordinary carts have no FD vehicle editor. Their controller therefore exposes a separate explicit service dispatch, which checks their original empty native certificate, complete linked train, stopped state, locked bridge and real fixed-powered native Chain departure. No hidden bed propulsion is introduced.
