## FD501

**Outcome:** Record usable core and per-adapter dependency decisions.

**Start conditions:** current core dependency inventory; read-only review can begin before [FD404](0.4-core.md#fd404).

**Read first:** [canonical scope, status and completion criteria](../../ROADMAP.md#fd501-select-the-expansion-dependency-and-migration-baseline); [dependency refresh](../INTEGRATION-BACKLOG.md#version-refresh-before-expansion), [dependency decisions](../INTEGRATION-BACKLOG.md#dependency-and-distribution-decisions), [build pins](../../gradle.properties), [migration procedure](../MIGRATION.md).

**Ordered steps:**

1. Refresh the dated catalog by its existing procedure; verify actual mod IDs, required dependencies and graphics/seat version constraints.
2. Separate the minimum new-vehicle core baseline from each optional adapter closure; name the consumer requiring each proposed upgrade.
3. Resolve whether a provider/format change is needed at all; document identity preservation and missing-provider behavior without adopting archived code wholesale.
4. Record compatible proposed profiles and chosen pins; release each completed decision immediately to [FD501A](0.5-contracts.md#fd501a) or the relevant B–H consumer.
5. Name unavailable upstream capabilities and their blocked consumers explicitly; finish the decision inventory without pretending blocked functionality works.

**Validation:** Metadata/API/dependency inspection first; native feasibility only for a named uncertain constraint. A routine latest-version update is not required after the decision.

**Finish and handoff:** [FD501A](0.5-contracts.md#fd501a) owns required core changes; B–H own adapter changes. [FD503](0.5-contracts.md#fd503) consumes decisions, not all optional upgrades. Record evidence and closure in the canonical package/current queue as applicable, then stop.

## FD501A

**Outcome:** Make the selected core baseline usable while preserving existing identities.

**Start conditions:** [FD404](0.4-core.md#fd404) and the recorded core decision within [FD501](0.5-contracts.md#fd501).

**Read first:** [canonical scope, status and completion criteria](../../ROADMAP.md#fd501a-apply-core-required-dependency-or-persistence-changes); [dependency refresh](../INTEGRATION-BACKLOG.md#version-refresh-before-expansion), [dependency decisions](../INTEGRATION-BACKLOG.md#dependency-and-distribution-decisions), [build pins](../../gradle.properties), [migration procedure](../MIGRATION.md).

**Ordered steps:**

1. Read the recorded core decision and identify exactly which new-vehicle consumer needs a dependency/provider/persistence change.
2. If the baseline is sufficient, record the permitted no-change disposition and close without a runtime replay.
3. Otherwise implement only the required core change on current main, preserving family/provider/vehicle identities and recovery fixes.
4. Check affected load/upgrade, missing-provider and backup-restoration behavior; integrate the passing change and expose the baseline to vehicle work.

**Validation:** Only checks justified by the chosen change. Optional-adapter migrations remain in their own packages.

**Finish and handoff:** Close for Wing and other core consumers; later adapter work does not reopen this decision absent a regression. Record evidence and closure in the canonical package/current queue as applicable, then stop.
