# 0.7 — Axis, Roller Ball and Flying

[Guide index and execution rules](README.md) · [Canonical roadmap](../../ROADMAP.md) · [Active assignments](../CURRENT-QUALIFICATION.md#current-work-queue)

Axis → Roller Ball and Conventional → New-generation Flying are separate dependency chains sharing one runtime owner at a time. Flying yaw is implemented in FD1802A and handed to FD1901A before Flying art or aggregate gates need to finish.

Card order helps navigation; actual prerequisites determine readiness. These are
procedures, not a second status tracker. Apply the index's evidence and stopping
rules to every step; already-covered steps do not require another run.

## FD1302A

**Outcome:** Working Axis mechanics and its required shared-contract handoff.

**Start conditions:** [FD501A](0.5-contracts.md#fd501a), [FD1501A](0.6-motion.md#fd1501a), [FD1301A](0.6-motion.md#fd1301a), [FD1302](0.5-contracts.md#fd1302)

**Read first:** [canonical scope, status and completion criteria](../../ROADMAP.md#fd1302a); [VehicleContract](../../src/main/java/dev/fourthdimension/contract/VehicleContract.java), [VehicleFactory](../../src/main/java/dev/fourthdimension/vehicle/VehicleFactory.java), [CarrierRuntime](../../src/main/java/dev/fourthdimension/runtime/CarrierRuntime.java), [occupied handoff](../../ROADMAP.md#shared-contract-handoff).

**Ordered steps:**

1. Consume [FD1302](0.5-contracts.md#fd1302) and the integrated prerequisites; identify reusable mechanics, lifecycle and occupied evidence before changing shared code.
2. Consume the integrated configurable-axis and bounded-motion infrastructure; implement the specified Axis pivot, range and free/driven modes.
3. Implement off-axis inertia, running gear, propulsion ownership and coupled swept clearance according to the Axis contract.
4. Implement rotation/capture transitions, upright unloading and the specified power-loss/rollback behavior without substituting Suspended swing rules.
5. Check affected native dynamics, eligibility, clearance and failure behavior, concentrating on off-axis clearance, mode/capture transitions and distinct camera/rollback behavior.
6. Complete the representative connected-client occupied boarding → motion → capture/stop → unload handoff with functional geometry. Check a new/changed synchronization path with a second real client; otherwise reuse accepted remote-rider coverage.
7. Integrate the passing contract into main and record its inputs, evidence and consumer handoff; do not wait for decorative polish.

**Validation:** Native checks cover the affected mechanism/invariants; connected clients cover normal input and rider/body/camera ownership. Retain unchanged prerequisite evidence. Off-axis clearance, mode/capture transitions and distinct camera/rollback behavior are the feature-specific focus.

**Finish and handoff:** Close [FD1302A](0.7-complex-motion.md#fd1302a) under its canonical criteria; hand the integrated interface to [FD1502A](0.7-complex-motion.md#fd1502a). [FD1302C](0.7-complex-motion.md#fd1302c) reuses the occupied proof. Record evidence and closure in the canonical package/current queue as applicable, then stop.
