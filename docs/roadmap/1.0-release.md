# 1.0 — Feature freeze, qualification and release

[Guide index and execution rules](README.md) · [Canonical roadmap](../../ROADMAP.md) · [Active assignments](../CURRENT-QUALIFICATION.md#current-work-queue)

FD1000 freezes the expanded scope after the required
[FD917 production visuals](pre-1.0-visual-production.md#fd917) are integrated and
accepted. Final qualification reuses accumulated evidence and checks outstanding
claims, including any new failures of that visual baseline. Foundational defects
can be fixed earlier; no new artifact starts qualification again. Publication
remains separately authorized.

Card order helps navigation; actual prerequisites determine readiness. These are
procedures, not a second status tracker. Apply the index's evidence and stopping
rules to every step; already-covered steps do not require another run.

## FD1000

**Outcome:** A feature-complete expanded 1.0 scope and identified qualification baseline.

**Start conditions:** [FD404](0.4-core.md#fd404), [FD503](0.5-contracts.md#fd503), [FD601](0.6-motion.md#fd601), [FD701](0.7-complex-motion.md#fd701), [FD813](0.8-operations.md#fd813), [FD915](0.9-presentation.md#fd915), [FD917](pre-1.0-visual-production.md#fd917).

**Read first:** [canonical scope, status and completion criteria](../../ROADMAP.md#fd1000-freeze-the-complete-expanded-feature-set); [canonical status and evidence](../CURRENT-QUALIFICATION.md), [gate blockers and follow-up work](../VALIDATION-POLICY.md#gate-blockers-and-follow-up-work).

**Ordered steps:**

1. Reconcile [FD404](0.4-core.md#fd404)/503/601/701/813/915 and all included vehicle/variant/integration outcomes using accepted evidence, plus FD917's new production claims.
2. Require the integrated FD917 models/materials, connected mechanisms, state/renderer changes and affected checks before freeze. Return missing assets, recipes, examples, guides or usability criteria to their owning packages; retain unchanged [FD916](0.9-presentation.md#fd916) evidence and accepted walkthroughs. The earlier UV review does not stand in for the new production target.
3. Freeze the included capability list, supported profiles/dependencies, production visual baseline, source/JAR and support limits in the current qualification record, preserving earlier identities and any deliberate FD917 contract/migration dispositions.
4. Record feature completion and move to stabilization; do not silently defer any adopted vehicle or capability to make the freeze pass.

**Validation:** Coverage and evidence review; run only checks for an actual unmet owning-package criterion. A staged addon or discovery result is not an implemented feature.

**Finish and handoff:** Release final [FD901](1.0-release.md#fd901)–[FD905](1.0-release.md#fd905) qualification; [FD801](external-compatibility.md#fd801), standalone builder tools, full multi-train management and moving-track work are outside the mandatory 1.0 gate. Record evidence and closure in the canonical package/current queue as applicable, then stop.
